# Reproducible GA4 extraction

For the current single-day authenticated workflow, use [foundation.md](foundation.md). This page preserves the earlier seven-day manual discovery approach.

1. Create or select your own Google Cloud project and enable BigQuery. No credentials are supplied or assumed. Google documents Sandbox as an exploration option. Use the BigQuery console, GoogleSQL, US data location.
2. First run `sql/00_event_inventory.sql` for January 1–7, 2021, inspecting estimated bytes before execution. Its first result lists event counts and distinct non-null pseudonyms; users overlap across events and must not be summed. Its second result supplies daily counts for export reconciliation. An inventory cannot establish ordered conversion or checkout abandonment. Then run `sql/01_schema_audit.sql`. Verify event_date STRING, event_timestamp INT64, event_name STRING, user_pseudo_id STRING, event_params repeated RECORD with key/value.int_value, traffic_source.source/medium, device.category, and items paths used by product SQL. Save audit results outside Git. Investigate duplicate ga_session_id keys before proceeding: MAX in extraction is a deterministic fallback, not a reconciliation strategy. The schema query inspects a November shard; inspect January shards too. The quality summary defaults to the full sample; narrow its bounds for initial discovery if needed.
3. Paste `sql/02_extract_events.sql`. It matches January 1–7, as do the funnel, product and browsing/segment queries. Inspect query validation and estimated bytes before execution. To use the entire sample, change both suffix bounds to `20201101` and `20210131` in extraction and matching queries. Never use an unbounded wildcard. Sandbox quotas and CSV download limits may require smaller windows or a user-managed export destination. Export the event-level extraction, not the aggregated inventory, as pipeline input.
4. Save results as CSV (not a screenshot) to `data/raw/ga4_events.csv`. Check export completeness against a COUNT(*) query using exactly the same bounds. If splitting exports, concatenate once with a single header and no overlapping windows. Keep all event names for browsing and retention analysis.
5. Record query text/hash, execution timestamp, date bounds, row count, bytes processed, export method, source table names, and schema audit outcome in a private extraction log. The local manifest adds input SHA256, actual date bounds, validation counts, and pandas version. Do not publish user identifiers casually.
6. Run the README command with label ga4. Review manifest missingness and row-count reconciliation before interpreting results. Compare `03_ordered_funnel.sql` against funnel.csv using identical bounds. This parity check is pending until cloud access exists.

The source's `traffic_source` describes first-user acquisition, not session attribution. No newer session attribution fields are assumed. Dates use exported GA4 event_date; UTC microsecond timestamps determine event order. Full-day boundaries can truncate sessions. Include adjacent shards if studying boundary sessions, then specify an entry-date rule before comparison.

Retention needs the full window and missing-day checks against expected dates; the seven-day extraction cannot support cross-month retention. The retention SQL intentionally retains the full November–January bounds. First/last partial months are incomplete and must be flagged in interpretation. Google warns about NULL, empty strings and `<Other>`; these become missing or Unknown locally. No missing identity is invented, and no absent cart event is backfilled.

Sources: [Google dataset prerequisites and caveats](https://developers.google.com/analytics/bigquery/web-ecommerce-demo-dataset), [GA4 export schema](https://support.google.com/analytics/answer/7029846).
