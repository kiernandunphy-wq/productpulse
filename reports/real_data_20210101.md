## Validation and limitations

- Existing suite: **27 tests passed**; Ruff passed. Dependency compatibility and repository package import passed.
- Independent BigQuery aggregates agree with Python for overall/device ordered counts and rates and unordered user KPIs. Source audit, inventory totals, export count and Python count all reconcile to 22,096. Every event-type inventory count and distinct-user count also matches Python.
- Manifest and analysis input SHA-256 agree: `74ed7b900c414fb1de39c97fe46ceacbec90f2813207e6c88a30b890a4c5cfa1`.
- Zero missing user/session rows, projected duplicates, excluded session rows, or repeated `ga_session_id` parameter keys. All four expected funnel event types are present. Required event dates/timestamps/names passed cleaning validation.
- Source and medium normalize to Unknown on **5,571** and **3,277** event rows respectively; device is never Unknown. These counts follow the existing missing/placeholder policy.
- **22 sessions** have no observed `session_start` event in this shard. No session-start prerequisite was introduced.
- There are **14 purchase events from 12 users**; **2 purchase-containing sessions** lack the full ordered funnel. Thus purchaser reach and completed ordered sessions differ. Missing steps are not backfilled; causes are not established.
- One calendar shard can truncate sessions. Obfuscated sample data, pseudonymous identities, missing acquisition values and strict ordering limit interpretation. These are within-shard observations, not complete customer journeys, transaction counts, revenue findings or causal conclusions.
